## 1. The shape — `goal → result`

The orchestrator is a **deterministic engine** (deterministic on *replay*, via the durable
journal — not because its steps are pure) that turns a **goal** into a **result**, emitting
a legible **event stream** the whole way so the run can be tracked, resumed, and (later)
paused for humans.

```
        goal (run input)
          │
          ▼
   ┌──────────────────┐   Slice B (planner selection): pick WHICH planner agent
   │ planner selector │   from the role‑classified library — deterministic rule
   │  (Rule | Llm)    │   OR a light reasoning call (journaled Pure effect).
   └──────────────────┘
          │  selected planner agent (role → reasoning chain via resolve_chain)
          ▼
   ┌──────────────────┐   Slice A: a journaled ReAct planner sub‑run under
   │  planner agent   │   "{expand}/__plan__". Pure discovery tools
   │  (drive_agent)   │   (list_agents/chains/skills/tools) + validate_plan.
   └──────────────────┘   Emits a right‑sized, self‑describing plan (native serde Graph).
          │  plan Graph (nodes carry NodePlan{label, description, needs})
          ▼
   ┌──────────────────┐   validate_dag + feasible() + caps → journal PlanExpanded
   │  splice (Expand) │   {node, subgraph} → reconstructed from journal on resume
   └──────────────────┘   (never re‑planned). This is the "memo for graph structure".
          │
          ▼
   ┌───────────────────────────────────────────────────────────┐
   │  executor / coordinator                                    │
   │  ready‑node scheduler over typed edges (Hard/Soft),        │
   │  cascade‑skip on failure; node kinds:                      │
   │    ModelCall · Agent · Map · Consolidate · Loop ·          │
   │    Subgraph · Branch · Expand                              │
   │  on a DURABLE JOURNAL:                                     │
   │    effect classes Pure / Observation / Mutation;           │
   │    two‑phase + in‑doubt→reconcile for Mutations;           │
   │    effect_id memo ⇒ resume WITHOUT re‑spending tokens;     │
   │    version fence; snapshots; compaction; CAS blob split.   │
   └───────────────────────────────────────────────────────────┘
          │  events: OrchestratorHooks + journal
          │  (run/node/agent/context lifecycle, on_plan_expanded, RunPaused)
          ▼
        result (sink outputs)     ── + real‑time flow‑tracking UX / alerts / HITL
                                     built ON the event stream (consumers, not core)

   under everything: the GATEWAY (sensei‑gateway) — chains, fallback, health gates
   (breaker/cooldown/lockout), budget/quota, panels/consensus, credentials.
   config: the REGISTRY (agents/skills/tools + role→chain bindings) loaded via a
   pluggable ConfigSource, hot‑reloadable, tenant‑agnostic, config‑driven (no DB yet).
```

**Load‑bearing invariants (hold across every slice):**

- **No silent failures.** Every error takes exactly one explicit path (`fail | pause | replan | retry | in_doubt→reconcile`), journaled + surfaced.
- **Deterministic replay / no re‑spend.** A completed effect is memoized by structural `effect_id` + input‑hash; resume replays it with zero gateway calls. Impure steps (LLM calls, the planner, an LLM judge) are made replay‑safe by **journaling their output once**, not by being pure functions.
- **Tenant‑agnostic core.** The gateway *and* orchestrator cores have no tenant concept; multi‑tenancy is a wrapper (one entity per tenant).
- **Config‑driven; persistence is opt‑in (SP‑DATA landing).** Everything runs on in‑memory config (`CatalogConfig → assemble → GatewayConfig`; `ConfigSource → Registry`). Durable persistence is the **SP‑DATA** layer, now landing behind backend‑agnostic seams: **`PostgresJournal`/`ContentStore`/`ContextStore`** (SP‑DATA‑1, `postgres` feature — feature‑off ⇒ byte‑identical) give cross‑process durable resume today; `PostgresConfigSource` + `config_versions` + the durable scheduler are the remaining SP‑DATA slices.
- **Opt‑in policy, light core.** Blackboard/hooks/CAS/reconcilers/planner are injected; unwired ⇒ the light path is byte‑identical.

## 2. The complexity ladder (planner right‑sizing)

The planner emits the **lowest tier that satisfies the goal** — a simple atomic task stays a
single‑level list; nesting/fan‑out/branching/runtime‑expansion appear only when the task
demonstrably needs them.

| Tier | Shape | Node kinds |
|---|---|---|
| 1 | single agent, single task | one `Agent` node (+ `NodePlan`) |
| 2 | parallel multi‑agent + consolidation | `Map{Agent bodies}` → `Consolidate{Agent}` |
| 3 | conditional · nested · iterative | `Branch` · `Subgraph` · `Loop` |
| 4 | runtime sub‑planning | `Expand` (recursive; caps‑bounded) |

Consensus/voting is **not** a tier of its own — it's `Map{blind voters} → Consolidate{evaluator}`
(bias isolation is already guaranteed: Map children run isolated and can't read siblings).

## 3. Decision log (asked → confirmed)

Grouped by phase. Each line is a confirmed decision; the per‑slice spec (§4 index) is canonical.

### SP‑0 — gateway health gates (merged; on `main` via PR #45)
- **Composable policy pipeline**, not subclasses: `AdmissionGate` chain + `RoutingStrategy` + `HealthRecorder` + `SelectionObserver`, composed via a builder.
- **Classification at the adapter boundary** (status/Retry‑After/body preserved); one pure `classify()` drives both in‑walk demote‑to‑tier and next‑request lockout. Deliberate `403 ≠ Authentication`.
- **Tenant‑agnostic health:** the gateway *announces* (`on_lockout`), the **caller persists** (`apply_lockout`/`clear_lockout`); the gateway never persists.
- **Durable pause vocabulary:** `GatewayError::AllGated{resume_after, skipped, human_action}` — timed ⇒ wall‑clock pause; all‑terminal ⇒ fail‑fast with a `HumanAction` hint. Invariant: `AllGated ⟺ every candidate gated AND none hard‑failed`.
- **`ResilienceConfig` at construction** (not a hot‑swappable `GatewayConfig` field), bounded eviction (expired‑only), deterministic keyed jitter (synthetic backoff only; default off).

### SP‑CAT + reference chains (merged)
- Free‑tier **catalog metadata** as optional `ModelConfig.catalog` (kernel, backward‑compatible); **tiers** = curated members ∪ attribute‑derived predicate (deterministic sorted); **pure `catalog::assemble() → GatewayConfig`** (tier‑ref chains → concrete `FallbackChainConfig`s; SP‑0 selection untouched). `cost_band` derived‑from‑pricing (override wins); `Headroom`/`LeastUsed` stub→`Priority` (need live usage).
- Portable **reference tiers + chains** (`research.bulk`, `plan.frontier`, `code.exec`) ship as editable reference data; chains stay user‑owned.
- **⚠️ USER DIRECTIVE:** the app stays **config‑driven, no persistence** — SP‑DATA is a separate, held‑off layer.

### SP‑1 — durable walking skeleton (merged)
- **slice 1 (spine):** 3 crates (`orchestrator-core` zero‑I/O · `orchestrator` engine · `orchestrator-store`). Linear Pure `ModelCall` graph; structural `effect_id(parent_path ‖ loop_iteration ‖ local_index)`; resume/fold memo ⇒ **no token re‑spend**; version fence; terminal‑guard.
- **slice 2 (agent runtime):** in‑memory `Registry` (frontmatter subset) + `NodeKind::Agent`; ReAct loop where **each turn is a Pure `ModelCall` effect** and each Pure tool call a Pure effect ⇒ resume‑without‑re‑spend extends *into* the loop; **two‑registry split** (core specs vs executable `ToolRegistry`); per‑turn window budget (halt‑loud, never truncate).
- **slice 3 (fan‑out · blackboard · CAS):** typed edges `EdgeKind{Hard,Soft}` + `validate_dag`; **ready‑node scheduler**; `Map` (internal bounded fan‑out) + `Consolidate` (+ `Aggregation::Quorum`, `min_viable` starve‑guard); **cascade‑skip on hard edges only** (soft‑dependents still run; failure suppresses `RunCompleted`); CAS split‑on‑output (ref‑or‑inline, lazy materialize); round snapshots (out‑of‑band); compaction primitive.
- **slice 4 (effects):** `Pure / Observation / Mutation` dispatched by `ToolSpec.effect_class`; Observation = memoize‑with‑TTL+provenance; Mutation = **two‑phase `EffectIntent`→`EffectRecorded`** + **`in_doubt→reconcile`** (`Confirmed | NotApplied | Indeterminate→RunPaused`); pause propagates out of a Map child loud (`MapChildPaused`).
- **blackboard wiring:** executor‑managed; a node publishes its output to `Run/node.id`; an Agent reads its **Hard deps' outputs only** (determinism: hard deps are completed+published+stable before the dependent runs). Resume rehydrates from journaled `ContextWrite`s.
- **Loop:** `NodeKind::Loop{body, input, gate, max_iters}`; **pure `LoopGate`** (no gate journaling); refine thread feeds prior text forward; cap‑without‑stop ⇒ best‑effort `{converged:false}`, never a bare fail.
- **Hooks:** `OrchestratorHooks` (no‑op defaults) fired from inside `append` ⇒ can't‑miss **and replay‑suppressed for free**; opt‑in ⇒ byte‑identical.
- **quota→pause:** pure `classify_gateway_error` — only `AllGated{resume_after:Some}` pauses (durable `RunPaused`); everything else fails. **Completes the SP‑1 skeleton.**

### SP‑2 — registry (merged; closes the registry phase)
- **slice 1 (ConfigSource):** `ConfigSource` is *the* extension trait (async, domain objects, no serialization in the contract); `Registry::from_config` is the single assembly point (dup names fail loud); `FilesystemConfigSource` isolates all md/JSON parsing.
- **slice 2 (role→chain):** `resolve_chain(agent, phase)` = per‑phase `chains[phase]` → explicit `chain` → `(area,kind)` binding → loud. **`(area,kind)` role table** with `chain` as optional override; **phase is a node attribute** (`Agent{…, phase}`), not a mid‑loop transition; **multi‑tenancy by composition** (per‑tenant Executor/Gateway/ConfigSource; no `tenant_id` in core).
- **slice 3 (tool permissions):** two‑sided **declaration** model (`ToolSpec.permissions` needs vs `AgentDefinition.grants`); `covers()` predicate; secure‑default deny/empty; central auditable `grants.json`; **runtime enforcement deferred to SP‑4** (declarations only; inert this slice).
- **slice 4 (activation policy, Q4):** **definition‑level** activation (`Activation{Always | OnKeywords}`); `assemble_prompt(…, query)` includes a skill/tool only when active; **query = node input, matched once per run** (determinism); planner‑selected & retrieval‑ranked activation **deferred** (planner‑selected → SP‑3; semantic → SP‑7). Orthogonal to permissions (security boundary) vs activation (prompt disclosure).
- **slice 5 (hot‑reload):** `RegistryHandle` (swappable `Arc<Registry>` + monotonic generation); `reload` is **atomic, validated, last‑good** (load+validate before the write lock); per‑run **pin** at entry; config generation folded into the fence version (`"{base}#cfg{gen}"`) ⇒ one config generation per run.

### SP‑3 — hierarchical executor (COMPLETE on `develop`)
- **slice 1 (Subgraph):** `NodeKind::Subgraph{graph}` driven as a nested DAG in the **same run** via `namespace_graph` + `drive`; output = **sink‑outputs map**; recursive `validate_dag`; **`max_depth`** cap. Fixed two reuse bugs: `finalize_run` moved out of `drive` (no premature `RunCompleted`); `ModelCall` effect‑id node‑scoped (no nested/outer collision).
- **slice 2 (Branch):** `NodeKind::Branch{on, arms, default}` + pure `BranchCond`; runs the first matching arm as a nested graph; **decision is pure over `on`'s memoized output ⇒ no branch journaling**; `on` must be a **Hard dep**. Lesson: any node kind referencing a sibling id (`Consolidate.over`, `Branch.on`) **must** be rewritten in `namespace_graph`.
- **slice 3 (PlanDelta / Expand):** `NodeKind::Expand{input}` + injected **`Planner` trait**; the produced graph is **journaled as `PlanExpanded` and reconstructed on resume — never re‑planned** ("memo for graph structure"). **`drive_nested`** extracted (3rd caller; retires Subgraph/Branch duplication). **Two‑tier failure:** planner/invalid‑plan/no‑planner → node `Failed`; cap breach → hard `Err`. **Caps** `max_expansions`/`max_nodes` seeded from the journal so they **span resume**.
- **slice 4A (planner agent):** `PlannerRef::{Agent, Injected}`; a **journaled ReAct planner sub‑run** at `"{expand}/__plan__"` via `drive_agent` → `PlannedGraph{graph, node_plans}`; pure `feasible()`/`parse_plan()`/`validate_plan` gate; `NodePlan{label, description, needs}` carried as the `PlanExpanded.node_plans` **side‑map**; Pure discovery tools; `on_plan_expanded` hook. Review caught a swallowed `DeterminismViolation` (→ `?`‑propagate) and a **feasibility gap** on nested `MapBody::Agent` refs (→ `check_agent_refs` recurses into Map/Consolidate/Loop bodies).
- **slice 4B (planner selector):** `PlannerRef::Select` + injected **`PlannerSelector`** (`RulePlannerSelector` pure + `LlmPlannerSelector` one‑call capability menu `name (area/kind)`); picks a **`planning`‑area** agent for the goal; **`PlannerSelected{node, agent}` journaled + folded** (resume reuses the pick) + `on_planner_selected` hook; anti‑hallucination `∉candidates`; extracted `drive_planner_agent`.
- **slice 5 (coordinator + loops‑of‑graphs) — CLOSES SP‑3:** `Loop.body: MapBody→**LoopBody**{ModelCall, Agent, Subgraph, Expand}` + `gate: LoopGate→**GateSpec**{Pure, Agent}`. **Subgraph body** = fresh re‑run each iteration (gate decides stop); **Expand body** = plan+execute+**refine** (thread the iteration output into the next planning input — the coordinator core); **gate‑agent** at reserved `"{loop}/{i}/__gate__"` (journaled answer → pure `stop_when`; this is the **graph‑body** convergence path, since a pure gate can't match a nested sink map — pure gate = leaf convergence). **`drive_expand_with`** extracted (shared by `run_expand` + Loop‑Expand); the run‑scoped caps **compose per‑iteration**. **The coordinator** = `Loop{ body: Expand{planner}, gate: Agent{…} }` — plan→execute→gate→replan, native + resume‑safe. Final whole‑slice review caught + fixed **`__gate__` not reserved in `feasible`** (an untrusted planner could emit a `__gate__` node → journal collision → resume `DeterminismViolation`) and an **unproven Expand refine** (input‑ignoring test planners) → added an input‑sensitive refine test.

### Planner brainstorm — SP‑3 slice 4 (design agreed 2026‑08‑13; **BUILT** — slices 4A + 4B merged)
*Split into **Slice A** (core + journaled planner) and **Slice B** (selector); the confirmed decisions below are recorded as the design rationale.*
- **Determinism framing (confirmed):** the engine is deterministic on *replay* (journal), not because the planner/consensus are pure. The planner and any LLM judge are non‑deterministic computations made replay‑safe by journaling their output.
- **Consensus (clarified):** a **blind, independent fan‑out + evaluator** (voters don't share context / see each other's answers — bias isolation). Already expressible as `Map{voters} → Consolidate{evaluator}` (Map guarantees isolation); a pure evaluator is deterministic, an LLM judge is journaled‑replay‑safe. **Not** the planner engine; a first‑class `Consensus`/`Vote` node or wiring the gateway's `execute_consensus` is optional/future.
- **Plan palette (confirmed):** **FULL** — the planner may emit every node kind incl. recursive `Expand`; the slice‑3 caps are the only backstop.
- **Planner mechanism (confirmed):** **ReAct planner with discovery tools** (`list_agents/chains/skills/tools` + `validate_plan`), grounded in what actually exists.
- **Deliberation durability (confirmed):** **journaled planner sub‑run** — `run_expand` drives the planner via `drive_agent` under `"{expand}/__plan__"`; ReAct turns are Pure effects ⇒ a mid‑plan crash **replays turns from the memo**. `PlannerRef::{Agent, Injected}` selects trait‑vs‑agent.
- **Self‑describing plan (confirmed):** `NodePlan{label, description, needs}` carried as a journaled **side‑map** `PlanExpanded.node_plans: HashMap<NodeId, NodePlan>` (keyed by local node id) — **not** a `Node` field (avoids a 94‑literal churn; core `Node`/`Graph` unchanged). `needs{skills,tools,agents,self_discover}` doubles as **planner‑selected activation** (the SP‑2 Q4 deferral); surfaced with the graph via `on_plan_expanded` so the UX/tracking see labels.
- **Right‑sizing (confirmed):** planner emits the lowest tier of the ladder (§2); flat single‑Agent for simple tasks.
- **Agent selection (confirmed):** a **role‑classified agent library** (= the SP‑2 registry) + a **selector** that picks the planner — **deterministic rule OR light‑LLM** (journaled) — → **Slice B**.
- **Decomposition (confirmed):** Slice A = `NodePlan` schema + `feasible()` + `validate_plan` primitive + journaled planner agent + discovery tools + `on_plan_expanded` hook; Slice B = `PlannerSelector` (Rule + Llm) + `PlannerRef::Select`.
- **Observability (confirmed):** the journal + `OrchestratorHooks` + `NodePlan` are the **flow‑tracking feed**; add the (previously‑deferred) **`on_plan_expanded`** hook so a UX gets the labeled plan in real time. **HITL** (`HumanGate`/`AwaitSignal` = SP‑6) and **human‑as‑Agent** are designed‑for consumers on the existing pause/resume + event substrate — deferred.
- **Feasibility (confirmed default):** checks registry‑resolvable refs (agents/skills/tools) + structure (`validate_dag`, distinct/non‑reserved ids, `"__plan__"` reserved) + caps; **chain‑existence is best‑effort in Slice A** (bad chain → runtime gateway error → node `Failed`).

### SP‑4 — permission/effect ENFORCEMENT + isolation (in progress on `develop`)
- **slice 1 (tool permission enforcement):** turns the inert SP‑2‑s3 `Permissions`/`covers()` **declarations** into runtime **authorization**. The gate lives at the single chokepoint `execute_tool_effect` (all Pure/Observation/Mutation calls route through it): a call is denied unless `tool ∈ agent.tools` AND `agent.grants[tool].covers(tool.required(args))`. **`Tool::required(&self,args)->Permissions`** (default = static `spec().permissions`) reports a call's **concrete** needs, so the grant is a *runtime ceiling* (narrower than the tool's max surface) — the load‑time full‑surface `validate` check is **dropped** (D3; a narrow grant is now legal, enforced per‑call). `covers()` hardened: **component‑aware paths** (`/work` ⊄ `/workspace‑secret`, empty‑path reject, `..` reject) + **host wildcards** (`*.example.com`). A denial is recorded as a **Pure `EffectRecorded`** (no tool run; **no `EffectIntent`** for a Mutation) and fed back to the agent as a **terse** tool‑result error (never enumerates the grant → confused‑deputy defense) ⇒ a resume replays the denial from the memo, tool never re‑invoked (mutation‑verified `effect_recorded_count==1`). **Trust boundary (stated):** this AUTHORIZES (stops the agent invoking un‑granted tools / an honest tool being *asked* to exceed the grant); it does NOT CONFINE a tool that under‑reports its `required` — runtime confinement + resource‑cap *killing* = the sandbox (slice 4). Whole‑slice review READY‑TO‑PUSH (single verified chokepoint; in‑doubt reconcile on resume re‑runs the gate ⇒ a revoked grant denies rather than re‑runs the side effect; additive — empty‑permission tools byte‑identical). **NEXT SP‑4 slices (provisional): s2 secret redaction · s3 workspace isolation · s4 sandbox + cred broker · s5 exactly‑once hardening.**
- **slice 2 (secret redaction):** scrub secrets from effect **outputs** before they are journaled or fed back to the agent, via a pure injected **`Redactor`** (`orchestrator-core`) — default **`PatternRedactor`** (curated secret‑shape patterns → `[REDACTED]`: OpenAI `sk‑`/`sk‑proj‑`, Anthropic, AWS, GitHub `gh[opsru]_`/`github_pat_`, Slack, Google, Stripe `sk_live_`, Bearer, PEM, `key=value` assignments; ReDoS‑safe `regex` automata). Opt‑in `Executor::with_redactor` (default off ⇒ **byte‑identical**). **The determinism crux:** redact **at production, before BOTH journaling and the agent/downstream‑return** (a journal‑only scrub would replay `[REDACTED]` on resume while live fed the secret → spurious `DeterminismViolation`); the redactor is **pure** ⇒ live == journaled == replayed, memo replays the redacted value. So the model never sees the secret (anti‑exfiltration) — credential *use* stays the sandbox/broker (s4). **Leaf sites:** the tool result (`record_tool_effect`) + **every model‑output producer via a single shared `model_output` chokepoint** (`dispatch_model_turn` [+`tool_calls` intact] · `ModelCall` node · `Map`‑item · `Consolidate`) + **the reconcile‑in‑doubt `Confirmed` output**; CAS blobs (`split_output` runs *after* redaction), `Map`/`Consolidate` sink maps, and `ContextWrite` inherit transitively. **Two plaintext leaks the reviews caught + fixed:** the Task‑2 review found redaction hit only 1 of 4 model‑output producers (→ `model_output` chokepoint); the **whole‑slice review found the reconcile‑in‑doubt `Confirmed` path** journaled+fed‑back a reconciler's Mutation output **unredacted** — a *silent* durable plaintext write on resume (no memo to fence) — fixed by redacting the Confirmed output (mutation‑verified). **Best‑effort by shape** (§4.4 — misses novel formats; precise known‑value/vault redaction is a future `Redactor` impl). **Carry‑forward:** reversible tokenization/crypto‑shred (SP‑DATA); entropy heuristic; redactor‑version in the fence; input‑side/plan‑structure redaction; a `leak_exec` test‑helper cleanup.
- **slice 5 (exactly-once — idempotency-key core):** make the SP-1-s4 two-phase Mutation mechanism deliver **real provider-side exactly-once** by closing the one gap — the `idempotency_key` was journaled but never reached the tool, so a real tool couldn't send it to an external API to dedupe on. **Additive `Tool` seams:** `call_ctx(args, &ToolContext{idempotency_key, effect_id})` (default → `call`) + `idempotency_key(args) -> Option<String>` (author override, default `None` → structural `sha256(effect_id|args_hash)`); `ToolRegistry::{execute_ctx, idempotency_key_of}`. **Executor:** `mutation_tool_effect` computes the **effective** key (author else structural), journals it in the `EffectIntent`, threads it to the tool via `call_ctx` (the tool sends the SAME key it journaled to its provider); `reconcile_in_doubt` **READS the journaled key** from `fold.intents` (changed `HashSet<EffectId>`→`HashMap<EffectId,String>`, D3) instead of recomputing — so on in-doubt resume the provider is queried by the exact key used at execution (robust for author keys). **Exactly-once proven both ways** (demo keyed "external system" store + `StatusQueryReconciler`): Confirmed-by-key records without re-invoking the tool (a raw `invocations` counter — distinct from the dedup-aware `calls` — pins "tool NOT re-invoked on resume"); NotApplied runs the effect once under the standing Intent (no 2nd Intent); an author-keyed variant proves `bk-77` journaled + reconcile-queried-by-it. **Absent provider → `Indeterminate` → `RunPaused`** (R3 mandatory-human-reconciliation, unchanged). **Additive:** default tools journal the structural key exactly as before, reconcile reads that same key ⇒ byte-identical (the whole SP-1-s4 in-doubt suite green); `ToolRegistry::execute` gated `#[cfg(test)]` (production dispatches only via `execute_ctx` — a call_ctx-bypass footgun retired). **Trust boundary:** makes exactly-once ACHIEVABLE (mechanism + key); true exactly-once still needs the provider to honor the key. **Carry-forward:** saga/compensation; retry-under-key; real provider API integrations; richer `ToolContext`; author-key purity/version fence.
- **credential broker (ephemeral secret injection):** lets a tool authenticate to an external system **without the secret ever touching the model or the durable journal** — completes the SP-4 arc (s1 *authorizes*, s2 *redacts*, s5 *exactly-once*, the broker *provides the credential out-of-band*). **`Secret`** (`orchestrator-core`, `Zeroizing<String>`, `[REDACTED]` Debug incl. `{:#?}`, no `Clone`, single audited `expose()`) + injected async **`CredentialBroker` trait** (`resolve(cred_ref) -> Option<Secret>`; demo `StaticCredentialBroker`; a real impl wraps `vault::Vault`). A tool **declares** its refs on `ToolSpec.credentials: Vec<String>` (`#[serde(default)]`) — declarative alongside s1 `permissions`; forced by the **async broker / sync `call_ctx` boundary** (the executor must resolve *before* the sync call). `record_tool_effect` resolves each declared ref via `Executor::with_credential_broker` (default none) and injects the `Secret`s into `ToolContext.credentials: Arc<HashMap<String,Secret>>` (Arc ⇒ clones share one store, zero plaintext copies) — **ephemeral: never journaled / hashed (`input_hash` is over `args`, computed before resolve) / re-injected on a memoized resume** (a completed tool replays its journaled secret-free output; broker not re-consulted — proven `resolves==0` on resume). **Echo-leak closed by a per-call exact-value scrub:** after the tool returns, the executor replaces every injected credential value in the output with `[REDACTED]` — **a pure fn of (this call's output, this call's creds)**, NOT a run-wide accumulating set (which would diverge across resume; D5). **Fail-loud:** a declared ref that resolves to `None`, has **no broker wired**, or whose broker **errors** → journal `NodeFailed` + `ToolOutcome::Failed`, tool never runs (never a silent missing cred). **Confused-deputy safe:** injection reads only the *called tool's own* `spec.credentials` — a tool can never see another's cred (which is why a per-call scrub suffices). **Whole-slice review caught + fixed a real leak:** the scrub originally ran **after** the s2 pattern redact — for a wrapped/composite secret (`wrap-sk-…`) the pattern would fragment the high-entropy span so the exact-value pass then missed the full value, leaking the `wrap-` prefix bytes into the journal + transcript → **fixed by scrubbing exact values FIRST, then pattern-redacting the residual** (both pure ⇒ determinism-neutral; TDD regression test). **Additive:** no broker + empty `credentials` ⇒ scrub over an empty set is identity, resolve loop a no-op ⇒ byte-identical. **Trust boundary (stated):** keeps the secret out of the model + journal and scrubs an accidental echo, but a tool is trusted to *use* the secret responsibly — true egress confinement is the sandbox (deferred). **Deferred (§6):** sandbox confinement + resource-cap *killing* (need a killable/confineable execution unit — blocked on the tool-execution-model), the real `VaultCredentialBroker`, per-tenant/per-agent credential scoping+grant, rotation/expiry mid-run.
- **workspace isolation (in-process jail + real fs tools):** makes the SP-4 arc concrete against a tool that actually does I/O — the executor had NO real tool I/O (all demo sinks) until this slice. Two REAL fs tools — **`fs_write`** (Mutation) + **`fs_read`** (Observation, ttl 0) — confined to a **durable per-run `base/<run_id>/` workspace** by an **in-process path jail**. **`Executor::with_workspace_root(base)`** (default none ⇒ byte-identical) → `workspace_root_for(run)` lazily `create_dir_all`s + **canonicalizes** the per-run dir (resolves base symlinks e.g. macOS `/var`→`/private/var`) and injects it into **`ToolContext.workspace_root: Option<Arc<PathBuf>>`** (ephemeral — never journaled/hashed; only the tool's `{bytes,path=RELATIVE}`/`{content}` output is). **The jail primitive `confine(root, requested)`** (orchestrator crate, uses `std::fs::canonicalize` so NOT core) rejects absolute/`..`/root/prefix components lexically + defends symlink-out by canonicalizing the **deepest existing ancestor via `symlink_metadata` (lstat)** and `starts_with(canonical root)` — the **lstat is load-bearing: `Path::exists` follows links so a DANGLING final-component symlink escaped (fixed in review)**. **Two-check enforcement (§4.4):** s1 authorizes (`grant.covers(required(args))`, runs first + rejects `..`/un-granted lexically) THEN the executor's jail pre-check confines every declared `need.paths` entry to the per-run root (a `WorkspaceEscape` → a **terse Pure denial** via `record_denied_effect`, no side effect, no `EffectIntent`, replayed on resume); the tools also re-`confine` (defense in depth). **The jail's UNIQUE value over s1** = per-run **isolation** (parallel/distinct runs → distinct dirs, which s1 cannot express) + **symlink/canonicalization** defense (s1's `covers` is purely lexical). **Determinism/resume:** a completed `fs_write` replays `{bytes,path}` from the memo — NOT re-run, file NOT re-written (proven by a SENTINEL-survives resume test); the per-run root is keyed by `RunId` ⇒ re-resolves identically. **s2 redaction composes** over real file content (a secret read back via `fs_read` is `[REDACTED]` in the journaled output + absent from the whole journal). **Additive:** no base wired ⇒ `workspace_root_for`→None, pre-check skipped, tools unregistered ⇒ byte-identical. **Honest limit (§4.4, stated):** an in-process tool with ambient fs authority that BYPASSES the shared `confine` helper cannot be prevented — that + cpu/mem/wall cap-KILLING + TOCTOU are the **deferred subprocess sandbox**. **Whole-slice review: SHIP** (3 defer Minors: no `fs_write` reconciler ⇒ in-doubt resume PAUSES loud like s5 [a naturally-idempotent re-write reconciler would auto-resume]; the pre-check confines EVERY path-declaring tool not just fs [fail-closed/safe]; redundant `workspace_root_for` calls [micro-perf]).
- **subprocess sandbox + resource-cap KILLING (s4, macOS-first):** runs an **external command** as a **killable, OS-confined child** — the capability the s3 in-process jail could NOT deliver (a sync in-process `Tool::call_ctx` has ambient authority + can't be killed mid-call). Finally **enforces the `ResourceCaps`+`NetworkPolicy` s1 only declared**. **Portable cap-killing core `spawn_capped(argv, caps, stdin)`** (`agent/sandbox.rs`, `nix` dep): spawns a child in its **own process group** (`process_group(0)`), applies `setrlimit(RLIMIT_CPU secs, RLIMIT_AS bytes)` in the post-fork hook, `kill(-pgid, SIGKILL)`s the **whole tree** at `wall_ms`; reader threads + off-thread stdin + a post-wait straggler-reap + **bounded output capture** (`recv_timeout(2s)` so a `setsid`-escaped descendant holding the pipe can't hang the caller — a whole-slice-review liveness fix). Portable all-unix (CI-tested on Linux via real subprocesses). **`Sandbox` trait + `SandboxSpec`** + **`MacosSandbox`** (`#[cfg(target_os="macos")]`) wraps `spawn_capped` in **`sandbox-exec -p <profile>`** (deny-default, broad file-READ [a binary must start], **WRITE confined to the workspace subpath**, network `(deny network*)` per `NetworkPolicy`); injected via `Executor::with_sandbox` (default none). **The airtight `BoundSandbox` seam (the crux):** the tool supplies only **argv** (untrusted); the executor builds a per-call `BoundSandbox{inner, workspace, caps, network}` from the **agent's grant** (`bound_sandbox_for` — the s1 ceiling) + the s3 per-run workspace, injected as `ToolContext.sandbox` — the tool **cannot widen** the policy (caps/workspace/network unreachable from args; e2e-proven for all three dimensions incl. a non-default `Hosts`). **`ShellTool`** (built-in, `shell`, Mutation): `required(args)`=`commands:[argv[0]]` (s1 authorizes the command; **strict argv** — a non-string element is a loud error so the gated command == the executed command, closing a fail-open); a cap-kill/nonzero-exit is a normal tool result the agent reacts to. **Refuse-loud (fail-closed):** no sandbox wired / non-macOS / no grant / no workspace ⇒ `ctx.sandbox: None` ⇒ `shell` refuses (a `NodeFailed`) — **NEVER an unconfined run**; the policy is NOT hashed/journaled (only the output); a kill is journaled-once; **s2 redaction composes** over stdout/stderr before journal+CAS; in-doubt resume → pause (R3, no reconciler). **Additive:** no `with_sandbox` + `shell` unregistered ⇒ byte-identical. **macOS confinement REAL (verified on the dev box):** write-outside DENIED / write-inside ALLOWED (the security proof), and `(deny network*)` blocks a **live loopback socket that `Any` allows** (a true positive/negative control, not a vacuous closed-port probe — empirically confirmed macOS Seatbelt blocks loopback egress). **Whole-slice review: SHIP** — one Important liveness bug FIXED (the `setsid` pipe-hang → bounded capture); the security crux (confinement, can't-widen, no profile injection [argv is a separate argv element], mem-cap **fail-closed on macOS** [Darwin `RLIMIT_AS`=EINVAL ⇒ a `mem_bytes` grant REFUSES, never a silent uncapped run], refuse-loud, additive, resume) all hold. **Deferred (§6): the Linux backend** (`landlock` fs + net-namespace egress + `seccomp`) — until then Linux runs refuse-loud; a `shell` reconciler for in-doubt auto-resume; precise network host allowlists (`sandbox-exec` Hosts→allow-all is coarse); read-confinement; **an output-size cap** (a command can flood parent memory before the CAS split — whole-slice Minor); BSD `pledge`/`unveil`; the `sandbox-exec`-deprecation migration.
- **Linux sandbox backend (s4 follow-on):** the `LinuxSandbox` (`#[cfg(target_os="linux")]`) that makes Linux/prod run `shell` CONFINED instead of refusing-loud — full macOS parity, **unprivileged**. **fs → landlock** (`landlock` crate, target-gated): WRITE confined to the per-run workspace (broad READ; a `/dev/{null,zero,full,random,urandom,tty}` WriteFile+Truncate carve-out for `2>/dev/null`), **ABI pinned to V5** (handles TRUNCATE/REFER/IOCTL_DEV) with `CompatLevel::BestEffort` for older kernels. **network → seccomp** (`seccompiler`, target-gated): denies `socket(AF_INET|AF_INET6|AF_PACKET)` + `io_uring_setup` → EPERM (surgical — `AF_UNIX`/`AF_NETLINK` allowed so programs start; the child `pre_exec` hook applies `restrict_self` THEN `apply_filter` (syscalls only, alloc-free + panic-free errno-only aborts) — avoids the fork+malloc-lock hazard; landlock before seccomp so the allow-by-default filter can't block `execve`. **Fail-closed (never an unconfined run):** an unbuildable ruleset / a `NotEnforced` restrict / a `Deny`-filter build-fail / an unsupported arch / no sandbox wired ⇒ refuse. **Target-gated deps + `#[cfg]` ⇒ macOS byte-identical** (the full macOS suite stays 1120). **Verified in Docker (unprivileged, landlock ABI 6 + seccomp — the dev box is macOS so it can't run natively) + `ubuntu-latest` CI:** write-outside DENIED / write-inside ALLOWED, a live-loopback egress deny/`Any` contrast, AF_UNIX-surgical, wall-kill composes, refuse-loud. **Whole-slice review CAUGHT + FIXED a CRITICAL fs-escape the per-task reviews missed:** landlock was pinned to `ABI::V1`, but `LANDLOCK_ACCESS_FS_TRUNCATE` is ABI v3 — landlock only mediates HANDLED rights, so `truncate(2)` was UNMEDIATED → a confined command zeroed a file OUTSIDE its workspace (proven in Docker) → fixed by `ABI::V5` (handles+grants TRUNCATE on the workspace, denies it outside) + a regression test. Two DEFER Minors: a `close_range(3,..)` in the child hook would harden egress against a future non-CLOEXEC inherited fd; `/dev/tty` write is a minor macOS-parity difference (not an escape).

### SP-DATA — persistence / control-plane (in progress on `develop`)
- **slice 1 (durable run state):** the first Postgres backend behind the backend-agnostic seams — **`PostgresJournal` / `PostgresContentStore` / `PostgresContextStore`** (`orchestrator-store`, `postgres` feature, **`sqlx 0.8`** runtime queries — not `query!`, so no compile-time DB) against a **dbd schema** (`gateway/database/`, torii convention: `journal_events` [`seq BIGSERIAL PK, run_id, event jsonb`] · `cas_blobs` [`digest PK, bytes`] · `context_refs` [PK `(scope_kind, scope_id, ctx_key)`] · `run_snapshots` · `runs` [`run_id PK, format_version`]). A run journaled in **process A resumes in a fresh process B** on the same DB — **ZERO token re-spend** (proven by a call-counter; the `EffectOutput::Ref` materialized from the durable PG CAS), durable in-doubt reconcile, and a **`format_version` fence** (`FORMAT_VERSION` const stamped on `RunStarted`, checked in BOTH `load`/`load_since` → `JournalError::IncompatibleFormat` LOUD ⇒ a v2 binary can't mis-fold a v1 journal). **Durability crux (whole-slice-verified):** `split_output` `put`s the CAS blob BEFORE the Ref is journaled (PG auto-commits the blob first) ⇒ a crash leaves at worst an **orphan blob, never a dangling Ref**; a missing blob is a LOUD `ContentDigestMiss`, never a silent mis-resume. The **fence has no bypass** — resume always `load`s (fenced) THEN appends; `latest_snapshot` (the one unfenced read) is never called in non-test code. Global `Seq` = **`BIGSERIAL`** (monotonic, matches the in-mem `AtomicU64`; fold-ordering only, never hashed; concurrent Map-fanout appends get unique seqs via atomic `INSERT … RETURNING`). New error taxonomy: **`JournalError::Backend`** (journal transport) vs **`OrchestratorError::Store`** (CAS/context transport) — distinct so a store fault isn't mislabeled a journal fault; both loud, never swallowed. **Additive:** feature-off ⇒ sqlx not compiled, **byte-identical (1120)**; NO executor/core change (the seam did its job). **Verified in Docker** (`postgres:16`, unprivileged on the macOS dev box): store PG suite 33/0 + cross-process-resume e2e 2/0 + schema idempotent re-apply. **Whole-slice review: SHIP** — no dangling-Ref, no fence bypass, no lost/dup seq, no swallowed durable error. Defer-Minors (§6): no cross-process *context* e2e (journal+CAS proven across the boundary; `PostgresContextStore` single-process parity only); pool sizing hardcoded (`connect()` `max_connections(8)`). **Human-on-the-loop (HOTL) noted, deferred:** the durable journal IS the observe-substrate for a supervisory control plane (observe+intervene); intervene lands with the management surface (s4). **NEXT SP-DATA slices:** s2 `PostgresConfigSource` + durable `config_versions`/`bump_config_version` (cross-process config fence) · s3 durable scheduler (re-arm a paused run at `resume_after`) · s4 management CLI/API (+ HOTL observe/intervene) · s5 cost/token budget model.
- **slice 2 (durable config-version fence):** closes a fence hole that only became reachable once s1 made runs resume **cross-process**. A run's determinism fence version is `"{base}#cfg{gen}"`; `{gen}` came from `RegistryHandle`'s **process-local, content-blind** counter, so across two processes it was meaningless in BOTH directions (false-negative silent mis-resume under changed config; false-positive spurious refuse of an identical config). This slice makes `{gen}` a **durable global generation**. **Second `ConfigSource` backend** — **`PostgresConfigSource`** (`orchestrator-store`, `postgres` feature): config content lives in **jsonb-row tables** (`config_agents`/`config_skills`/`config_tools` [name-keyed jsonb] + a natural-row `config_chain_bindings` + a single-row **`config_versions`** [`id boolean PK check(id)`]); `load()` reads the whole registry, `version()` reports the durable generation (**always `Some`**; absent row ⇒ `Some(0)` — `None` is reserved for unversioned filesystem/in-memory sources), `store` (replace-all in one txn) + **`bump_config_version`** (app-side atomic upsert-increment, no DB function needed) are the write path. **Trait wiring (additive):** `ConfigSource` gains a **defaulted `version() -> Option<u64>`** (`None` ⇒ unchanged local counter); `RegistryHandle::reload` pins `Some(v)` as the generation else `+1`; new `RegistryHandle::from_source` boots at the durable version. **The payoff (cross-process e2e, mirroring s1's):** unchanged config → a fresh process resumes (fence matches, **zero re-spend** `calls_b==1`); a **bump** → a fresh process refuses **loudly** (`VersionFenceMismatch{recorded:"v1#cfg{v}", current:"v1#cfg{v2}"}`) — never a silent wrong-config resume. AC2 proves `AgentDefinition`/`ToolSpec` round-trip through jsonb **including nested grants/permissions/credentials/input_schema**. **NO executor/fence change** — the `.pinned`/`VersionFenceMismatch` machinery is untouched; s2 only makes `{gen}` durable. **Additive:** feature-off ⇒ byte-identical (1120 → **1123**, +3 core wiring tests). Verified in **Docker** (`postgres:16`, store 38/0 + e2e 4/0). **Whole-slice review: SHIP** (fence closes both directions, `version()` never `None`, schema↔adapter exact, all errors loud); dbd-pattern-verifier **conformant** (`dbd doctor`/`inspect` clean, 11 entities). **Two Important carry-forwards to SP-DATA-4 (both UNREACHABLE this slice — `store` is test-only, reloads serialized — so they ship, but MUST close before a live concurrent config writer):** (1) **load()/version() TOCTOU** — the two reads (and `load()`'s own four-table read) are non-atomic, so a concurrent `store+bump` could hand a reload **(stale config, fresh gen)** → a run stamps a fresh-gen fence over stale config → a later resume reads the consistent (fresh,fresh) and matches → silent wrong-config resume; **re-versioning at resume does NOT neutralize it** (the initial doc claim was corrected); fix = read the four config tables + `config_versions` in ONE `REPEATABLE READ` snapshot (`load_versioned()`). (2) **generation-only fence** — a `store()` without a `bump()` changes content without advancing the gen → same-gen silent wrong-config resume; the SP-DATA-4 CLI must **couple store+bump** (one txn / a `store_and_bump` helper).
- **slice 3 (durable scheduler):** turns a `RunPaused{resume_after}` from a dead-end into a **self-healing pause** — a durable driver that wakes a paused run at its deadline, in any process, exactly-once, zero re-spend. **The crux — graph recovery:** `Executor::start(run, graph)` takes the graph as a caller param and the graph isn't journaled; since `Graph` is `Serialize`, the **scheduler owns the original graph** in a `scheduled_runs` table (executor UNCHANGED). **The correctness insight — waking is idempotent** (fold+memo, zero re-spend; in-doubt→reconcile), so a double-wake is SAFE — exactly-once is tidiness (don't thunder), not correctness. **Pieces:** a `SchedulerStore` trait (core) + `InMemory`/`Postgres` impls (store) + a **`Scheduler`** driver (orchestrator, holds an injected `Executor`+`Clock`+the journal). `submit` enqueues the graph + drives + records; **`tick()`** atomically **claims due wakes** (`UPDATE … WHERE run_id IN (SELECT … FOR UPDATE SKIP LOCKED) RETURNING` — exactly-once vs a fleet + a **lease** reclaims a crash-mid-wake stale `'waking'`) + re-drives `Executor::start`. Clock-injected so tests advance a fake clock (no real sleeps). **Reads the pause deadline from the durable journal's last `RunPaused`** (the executor's `PauseInfo` doesn't carry it, and threading it up through every `NodeExec::Paused` producer was rejected as invasive — so ZERO executor change). **The two natural wake classes (a clean fallout):** `resume_after=Some(t)` (quota→pause) → auto-woken at `t`; **`resume_after=None`** (in-doubt Mutation pause) → `next_wake` NULL → never auto-woken → needs **`force_wake`** (a human resolves the mutation, then force-wakes) — the **HOTL** path, for free. **Observe** (`status`/`list_paused`) + **intervene** (`cancel` [→ never woken; `record_paused`/`record_terminal` are conditional on `'waking'` so cancel WINS mid-drive], `force_wake`) ship this slice (the user chose driver+observe+intervene over defer-intervene). **SP-DATA-2 composes:** a wake whose config generation drifted → `VersionFenceMismatch` on `start` → the driver records the run terminal-`Failed` ("stale: config changed") — loud, never a silent resume under changed config. **Verified in Docker** (`postgres:16`): store 47/0 (incl. a **concurrent-claim exactly-once** test + lease-reclaim) + the **cross-process durable-wake e2e** (process A pauses + persists to PG; a FRESH process-B Scheduler sharing NOTHING in-process reads A's durable pause and `tick`s it to completion). **Additive:** 1123 → **1131** (+6 store + 2 driver tests), executor/core byte-identical otherwise. **Whole-slice review: SHIP** — caught + fixed a cross-suite **test-isolation bug** (the e2e's global `tick()` swept the store suite's ancient-timestamp `'waking'` rows → an over-specific `tick()==1` assertion; relaxed to a per-run outcome assertion, the correct convention). **Deferred:** an explicit AC8 fence-composition e2e (the `record` arm exists, untested); backoff/jitter/max-attempts; terminal-row pruning; a production `run_forever` supervisor; `LISTEN`/`NOTIFY` low-latency wakes. **NEXT: SP-DATA-4 management CLI/API** (built on `list_paused`/`status`/`cancel`/`force_wake`; + close the SP-DATA-2 TOCTOU/store-bump carry-forwards) · **SP-DATA-5 cost/token budget**.

- **SP‑DATA — persistence/control‑plane (IN PROGRESS):** ✅ **s1** `PostgresJournal` + persistent CAS + `format_version` fence (cross‑process durable resume, merged). ✅ **s2** `PostgresConfigSource` (config as jsonb rows) + durable **`config_versions`/`bump_config_version`** — the **cross‑process config fence** (`#cfg{gen}` is now the durable global generation; merged). ✅ **s3** the **durable scheduler** — a `Scheduler` driver over a `scheduled_runs` `SchedulerStore` that wakes a paused run at its `resume_after` in any process, exactly-once (atomic claim + lease), zero re-spend; observe (`status`/`list_paused`) + intervene (`cancel`/`force_wake`); the `resume_after=None` in-doubt pause → `force_wake` = the HOTL path (merged). Remaining: management CLI/API (torii‑derived, + human‑on‑the‑loop observe/intervene) (s4); cost/token budget model (s5). **Carry‑forwards into s4 (from the s2 whole‑slice review, unreachable until a live config writer exists):** make config reads atomic (`load_versioned()` = one `REPEATABLE READ` snapshot over the four config tables + `config_versions`) to close the (stale‑config, fresh‑gen) TOCTOU; and **couple `store`+`bump`** in the CLI (a `store`‑without‑`bump` is a silent‑wrong‑config footgun, since the fence is generation‑based).
